Install OneAgent on Kubernetes using Helm with ActiveGate Proxy

This guide explains how to install Dynatrace OneAgent on Kubernetes using the Helm method, and configure a standalone ActiveGate as a proxy for your Dynatrace SaaS environment.

Prerequisites​

  • Kubernetes cluster access
  • ActiveGate .p12 file with custom CA
  • Helm CLI
  • Dynatrace API Token and data ingest token
  • Dynatrace environment ID

1. Extract the Custom CA Certificate​

Extract the custom-ca.crt file from your activegate.p12:

openssl pkcs12 -in activegate.p12 -nokeys -out custom-ca.crt

2. Install Dynatrace Operator with Helm​

Install the Dynatrace Operator from the public OCI Helm registry:

helm install dynatrace-operator oci://public.ecr.aws/dynatrace/dynatrace-operator \
  --create-namespace \
  --namespace dynatrace \
  --atomic

3. Create the ConfigMap with CA Certificate​

Add your custom certificate as a ConfigMap:

kubectl create configmap custom-certs \
  --from-file=certs=custom-ca.crt \
  -n dynatrace

4. Define the DynaKube Custom Resource​

Create a YAML file with your DynaKube configuration.

Sample YAML (dynakube.yaml)

Copy
Edit
apiVersion: dynatrace.com/v1beta3
kind: DynaKube
metadata:
  name: dynatrace-lab
  namespace: dynatrace
  annotations:
    feature.dynatrace.com/k8s-app-enabled: "true"
spec:
  apiUrl: https://&lt;activegate-host&gt;:9999/e/&lt;environment-id&gt;/api
  trustedCAs: custom-certs
  skipCertCheck: true

Replace <activegate-host> and <environment-id> with your actual values.

5. Apply the DynaKube Resource​

kubectl apply -f dynakube.yaml

Verify the Deployment​

Check the status of the DynaKube and Pods:

kubectl get dynakube -n dynatrace
